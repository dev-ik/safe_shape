# SafeShape 3.3: проверяемые выходы и эффективный runtime

[English](../implementation-plan-3.3.md) | **Русский**

Реализация завершена, подготовлен кандидат версии 3.3.0, релиз не опубликован.
Финальная квалификация кандидата ещё не завершена. Миссия — лучшая платформа runtime-контрактов TypeScript: корректность
перед производительностью, immutable-схемы, богатая диагностика, стабильный API.

## Порядок работ

1. RFC 0049 и ADR 0037: отдельные output bounds для pipelines, JSON Schema и связей
   живых схем. Точный IR/snapshots сохраняются, производимость не угадывается.
2. Профилирование и оптимизация async discovery/слоёв без checks без потери Error,
   stack, issue trees, warnings и замороженных контейнеров.
3. Runtime/type тесты рекурсии, async, bounds/export и консервативных связей;
   сквозной пример из установленных архивов.
4. Обновление EN и перевод всех актуальных пользовательских/API/операционных
   руководств. Примеры/defaults согласованы; inventory защищает от пропусков.
   Исторические release evidence и нормативные RFC/ADR отмечены EN.
5. Package tests, build/typecheck, docs/examples/consumer/migration, замеры и полный
   release gate. Ошибки и ограничения записываются явно.

## Приёмка

Без breaking API/snapshot/default export. Checked string→number экспортирует
явную numeric output-bound и доказывает связь с более широким native consumer.
Невключённая граница даёт manual review, не выдуманный контрпример.
Финальный opaque transform остаётся неподдержанным. Reports неизменяемы;
callbacks не исполняются, lazy-getters разрешаются по прежним правилам.

Замеры используют прежние workloads/budgets, показывают улучшения и оставшийся
разрыв с Zod. Собственные бюджеты не означают паритет. Русское оглавление ведёт
на русские актуальные страницы; API имеют примеры EN/RU и тесты. Inventory
контролирует отсутствие страниц/изменение источников, но не качество перевода.
Независимый developer walkthrough — отдельное человеческое свидетельство.

Расширение formats/defaults/codecs отложено до подтверждённой потребности и
отдельной спецификации. Публикация — отдельный шаг после квалификации.
