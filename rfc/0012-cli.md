# RFC 0012: cli

## Motivation

SafeShape needs a command-line entry point for local tooling workflows such as exporting
JSON Schema from schema modules.

## Proposal

Add `@safe-shape/cli` with the `safe-shape` binary.

Initial commands:

- `safe-shape --json doctor`
- `safe-shape schema export --module <file> --export <name>`
- `safe-shape schema validate --module <file> --export <name> --input <file|-> --out <file>`
- `safe-shape schema types --module <file> --export <name> --name <type>`

The CLI loads JavaScript ESM modules by explicit file path and named export.

`schema export` emits JSON Schema through `@safe-shape/json-schema`.

`schema validate` reads a JSON file, or stdin when `--input -` is used, and
validates it through the loaded schema. Successful validation exits with `0`;
validation failures exit with `1` and emit stable SafeShape issues under
`--json`. `--out` writes the full validation report to a file.

`schema types` emits a TypeScript type declaration from runtime schema
introspection. Transform output types are emitted as `unknown` because mapper
return types are not available at runtime.

## JSON Policy

Commands that receive `--json` return a stable JSON envelope.

Success output includes `ok: true` and the command name.

Errors include `ok: false`, the command name, and `{ code, message }`.

The CLI does not require auth and must not print secrets.

## Alternatives

- Load TypeScript schema files directly. This is deferred to avoid adding loader/runtime
  complexity in the first CLI version.
- Validate non-JSON input formats. This is deferred because SafeShape should keep
  JSON validation explicit before adding format loaders.

## Migration

No migration is required because the CLI is additive.
