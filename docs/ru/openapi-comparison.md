# Сравнение документов OpenAPI

[English](../openapi-comparison.md) | **Русский**

SafeShape 4.0 напрямую сравнивает два документа OpenAPI 3.0/3.1. Контракты можно
хранить в YAML или JSON без параллельных схем SafeShape, поддерживаемых вручную.

```ts
import { readFile } from 'node:fs/promises';
import { compareOpenApi } from 'safe-shape'; // также @safe-shape/api

const report = compareOpenApi(
  await readFile('previous.openapi.yaml', 'utf8'),
  await readFile('next.openapi.yaml', 'utf8'),
);
console.log(JSON.stringify(report, null, 2));
process.exitCode = report.compatible ? 0 : 2;
```

Первый документ — действующий контракт сервера, второй — предлагаемая замена.
Операции сопоставляются по HTTP-методу и пути. Адаптер импортирует используемые
схемы внутри, а `@safe-shape/compat` доказывает включение допустимых значений.
Запросы должны продолжать принимать данные старых клиентов; ответы должны
оставаться в пределах, которые старые клиенты принимают. Например, новое
обязательное поле запроса нарушает совместимость, необязательный query-параметр
совместим, а удаление операции несовместимо. Также сравниваются наследуемые
параметры, тела, JSON media types, заголовки и выбор ответа по HTTP-статусу.
Сетевые запросы к API не отправляются.

Читайте обе части неизменяемого отчёта:

- `findings`: изменения операций и доказательства совместимости с endpoint и путём в документе.
- `issues`: ошибки импорта или неподдерживаемые конструкции с указанием previous/next.

`compatible` равен true только при `decision: 'compatible'`. `migration-required`
означает несовместимое изменение, `manual-review` — недостаточность автоматического
доказательства. При ошибке импорта возвращаются manual-review и пустые findings.
Пустой список findings не доказывает совместимость, если есть issues.

Релиз поддерживает описанное подмножество OpenAPI. Локальные ссылки и рекурсивные
схемы с продуктивной рекурсией поддержаны; внешние ссылки, oneOf, проекции
readOnly/writeOnly, callbacks, webhooks и не-JSON тела требуют проверки.
Неподдерживаемые ограничения не отбрасываются. Изменения авторизации и серверов
консервативно дают manual-review. Неиспользуемые компоненты не сравниваются.

По умолчанию format отклоняется: аннотации OpenAPI и runtime-валидаторы могут
иметь разные правила. `{ formatPolicy: 'annotation' }` трактует форматы только
как документацию; `{ formatPolicy: 'safe-shape' }` применяет правила SafeShape
для email/uuid/date/date-time. Annotation-режим не обнаруживает изменения только
format и не проверяет числовую разрядность. [API-справка](api/api.md) содержит
точные ограничения, лимиты и типы отчёта. [Исполняемый пример](../../examples/openapi-comparison.mjs)
проверяет несовместимое изменение и совместимое обратное изменение.

Функция принимает текст или разобранные объекты и не читает файлы/сеть сама.
Прямое сравнение документов доступно через JavaScript API; `safe-shape api check`
по-прежнему сравнивает snapshots каталогов SafeShape.
