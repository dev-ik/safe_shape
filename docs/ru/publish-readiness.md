# Готовность к публикации

[English](../publish-readiness.md) | **Русский**

Публикация выполняется после явного разрешения и проверки конкретного кандидата.

- Состав релиза и список публикуемых пакетов определены.
- Root/workspace версии и внутренние зависимости согласованы.
- Breaking API имеют RFC; новые API имеют тесты и документацию EN/RU.
- Архитектурные изменения имеют ADR, направление зависимостей сохранено.
- Workflow публикует все пакеты по зависимостям, общий пакет — последним,
  уже существующие npm-версии пропускает.
- Интеграция и руководства миграции соответствуют кандидату.
- Docs-check проверяет ссылки, переключатели языка, покрытие и актуальность источников.
- Вручную проверьте версию и статус в README, навигации и release notes.
  Docs-check проверяет структуру и рассмотренные хеши, но не доказывает публикацию.
- Старые разделы «Новое в» перенесены в историю релизов.
- Примеры, benchmarks, consumer install и release:check проходят.
- Результаты CI и независимого walkthrough записаны отдельно от локальных тестов.

```sh
npm run build
npm run consumer:check
```

Consumer-check упаковывает пакеты и устанавливает в .tmp/consumer-check/app,
проверяет публичные импорты и установленный CLI.

После разрешения: prepare:release, commit подготовленной версии, push ветки,
аннотированный тег v<version>, запуск publish workflow на теге в фазе release.
Compat-only предназначен только для восстановления старой частичной публикации.
Не публикуйте посторонние пакеты.

## MCP-пакет (3.5.0)

Включите `@safe-shape/mcp` в релиз десяти пакетов и настройте npm trusted publisher
для того же repository/workflow/environment. Consumer-check проверяет установленный
MCP executable и адаптер инструментов вместе с CLI. `prepare:release` создаёт
десять архивов и SHA256SUMS. Walkthrough реального coding-агента фиксируется
отдельно от SDK-тестов; см. [MCP](mcp.md).

## Проверка после публикации

- Дождитесь доступности всех версий и `latest` в npm. Проверка пакетов при
  публикации может задержать установку после успешного `npm publish`.
- В новом consumer установите только `safe-shape@<version>`, проверьте root/MCP
  imports, handlers и оба CLI-бинарника.
- Скачайте архивы GitHub Release и проверьте SHA256SUMS.
- Вместе обновите EN/RU-статус проекта, навигацию, roadmap, release notes,
  историю релизов и актуальный статус release evidence.
- Сохраните датированные проверки до публикации как явно обозначенную историю.
- Зафиксируйте provenance и исключения для первой ручной публикации.

Опубликованную пару имя/версия npm нельзя заменить. Правки packaged README,
включая закреплённые на версию ссылки, требуют нового patch-релиза; изменение
`main` не обновляет установленный архив или предыдущий тег.
