# Обновление с SafeShape 3.0 до 3.1

[English](../migration-3.0-to-3.1.md) | **Русский**

3.1.0 опубликован 11 сентября 2026; рекомендации применимы и к прямому переходу
3.0→3.2. Обычные single-contract команды и форматы snapshots сохранены.
Check-many — отдельный opt-in сценарий: ошибки записей идут в stdout, неверный
manifest — в stderr.

Два исправления корректности могут менять результаты:

- RFC 0043: равные literal leaves внутри эквивалентных v2 unions/wrappers больше
  не дают ложный breaking. Opaque guards остаются консервативными.
- RFC 0044: собственные __proto__ поля и lazy-id сохраняются в описаниях,
  snapshots и JSON Schema. Раньше потеря могла дать ложную безопасность.
  Required не может удовлетворяться только унаследованными ключами.

Для baseline с такими полями/id сравните собственные свойства с runtime-схемой.
Некорректный baseline теперь может отклоняться, исправленный — менять fingerprint.
Пересоздавайте только после review схемы и последствий для сторон, не массово
ради прохождения CI. Обычные snapshots сохраняют представление.
Тестовые свидетели подтверждают проверенный домен, не произвольные callbacks.
